压缩生成式召回的行为序列

本期关注 PinGER 怎样用非对称注意力压缩历史商品的表示，使有限上下文能容纳更多用户行为。

Section 1: 📊 Trend Analysis

  • 🔥 生成式检索进入"工程深水区"：今日 3 篇工业界生成式召回论文（Pinterest PinGER、阿里 SLIDE、Octen-WebGR）不再比拼"能不能生成"，而是聚焦 token 效率、单次贪心解码替代 beam search、单卡低内存服务等落地细节。核心矛盾从"效果"转向"成本-延迟-规模"三角约束，Semantic ID 已成为标配表示。
  • 💡 LLM 推荐的"降本"主线清晰：CRIM 用可复用物品记忆缓存解耦编码与请求建模，AgentMemRec 把记忆选择建模为预算 slate 推荐且零 LLM 调用，DICE 用树结构注意力实现 6× 加速——三条路径都在回答同一个问题：如何在不牺牲个性化质量的前提下砍掉重复的 LLM 推理开销。
  • 📐 传统信号的理论再审视：两篇 University of Antwerp 论文分别从概率建模重推 item 相似度、揭示用户活跃度导致的"幻影相关"，提醒工业界 item-CF 的相似度信号中混有大量活跃度伪关联，去偏值得纳入召回链路。

Section 2: 📋 今日速览

  • Pinterest 在 Related Pins 场景提出 PinGER 生成式召回，用非对称注意力掩码让训练时每个 SID 位置受监督、服务时每物品仅一个 token 压缩历史。线上新 Pin saves +3.60%、整体 saves +0.62%，端到端延迟 -0.7%。↗
  • Alibaba 在淘宝搜索提出 SLIDE 蒸馏框架，将离线 beam search 的跨物品候选按 beam 分数拼接为列表级蒸馏目标，学生单次贪心生成 Top-K。单贪心解码下检索质量大幅提升，强教师下超越 beam search 基线。↗
  • Octen 将 2.01 亿网页存入 4B 语言模型参数，生成两 token 语义标识符并约束到真实 URL 表。导航搜索 top-1 达 59.6%（稠密检索 46.5%），单 GPU 10GB 内存运行，成本仅为前沿 LLM 的 1/40。↗
  • Alibaba 提出 HiRank 统一精排框架，用有效秩视角融合门控序列注意力与异构特征交互，场景感知聚合压缩低阶 token 缓解多场景负迁移。线上 A/B 订单/用户 +2.27%，工业规模数据集稳定优于基线。↗
  • Alibaba, Tsinghua 提出 CRIM，用少量 summary token 将物品压缩为可跨请求复用的连续记忆，配合 REC token 段级监督与缓存+采样重编码联合训练。三个数据集达 SOTA 检索性能，推理成本显著降低。↗
  • University of Antwerp 从概率建模角度重新推导 item 相似度，基于伯努利与多项分布导出两种新度量，并将余弦相似度解释为特定优化问题的解。为传统启发式相似度提供理论支撑与消融分析。↗
  • Unknown 将 Agent 长期记忆选择形式化为预算 slate 推荐，复用召回-精排-slate 构造级联且全程零 LLM 调用。LongMemEval 上比 A-Mem 等方法高 10-31 分，成本比 LLM reranker 低 3.2 倍。↗
  • Arizona State University 提出 DPE-Rec 扩散语言模型捆绑包推荐，用语义分叉感知 GRPO 保多样性、伪轨迹蒸馏实现多 token 解码。推荐性能平均 +63%，快速版推理提速 25.6×。↗
  • Chiang Mai University 证明可从闭式线性自编码器权重矩阵直接发现潜在主题，无需额外训练，并提出抑制热门物品/活跃用户主导的归一化。六个数据集主题质量超专用主题模型，推荐性能保持竞争力。↗
  • Skoltech, HSE, Sber AI Lab 提出仅通过用户表示级 adapter 迁移的跨域序列推荐，不共享原始交互与物品嵌入，无源域数据时自动退化为目标域模型。两种实验设置下共享与非共享用户均获稳定提升。↗
  • Gamaizer, UTC, Sorbonne 提出 CA-HNM 约束感知难负样本挖掘，用结构化领域模型的不兼容规则筛选负样本微调双塔。8 组配置中 6 组 NDCG@10 优于匹配对照，4 个 bootstrap 区间全为正。↗
  • Shenzhen University, McGill 提出 OptIDC 统一样本/特征/嵌入单元三级输入侧配置，用选择加权最优传输协调跨层冲突，模型无关可插拔。四个真实数据集 AUC 一致优于现有输入侧选择方法。↗
  • University of Antwerp 揭示 item-item 相似度中大量关联源于用户活跃度异质性而非共同偏好，用 Rasch 模型推导"幻影相关"并量化各相似度度量的受影响程度。对协同过滤中 item 共现信号的解读提出警示。↗
  • University of Toronto, Vector Institute 提出 ACARe 用 agent 推理上下文条件化 4B 重排器，让文档匹配原始问题而非仅子查询。多 benchmark 与 agent 家族上检索质量提升、搜索轮次减少，并帮助小 agent 缩小与大 agent 的差距。↗
  • UNSW, Hunan University, Sydney 提出 HyperAddress，用 LLM 中识别出的 addressing heads 引导超图个性化 PageRank，实现查询时零生成的多跳检索。三个数据集 Recall@5 平均 +3.5、All@5 +7.4，回答速度 2× 以上、索引成本减半。↗
  • Emory University, Notre Dame 提出 SkillQR 从检索目标自动发现重写策略集并在推理时动态路由，无需训练数据。BRIGHT 与 R2MED 上媲美微调重写模型，推理延迟低于迭代重写方法。↗
  • USTC, NUS 提出决策原生推荐范式 DICE，用树结构注意力在单次前向中实现候选顺序一致打分并输出校准置信度。三个数据集 top-1 准确率超所有基线，端到端较生成式方法加速约 6×。↗
  • Unknown 提出 LoopGR 以循环深度作为生成式推荐新扩展维度，交替共享解码器与轻量上下文更新器，并用循环轨迹自蒸馏压缩推理预算。性能优于强基线同时模型规模减少最多 52%。↗
  • University of Technology Sydney 提出 MIDA 双空间解耦多兴趣解码框架，在原始 embedding 上聚类保留语义结构、以簇大小为条件门控融合稳定性与可塑性分支。多数据集稳定优于 SOTA，缓解长会话性能下降。↗

Section 3: 📰 Daily Digest

1. PinGER: Token-Efficient Generative Retrieval with Semantic IDs

🔗 原文： https://arxiv.org/abs/2610.33435

🏷️ 来源： 🏭 工业界 | Pinterest

⭐ 评分： ⭐⭐⭐⭐ (4/5)

🎯 推荐理由： Pinterest 线上部署的 token 高效生成式召回，非对称掩码压缩历史并带来 saves 提升。

📝 摘要： 针对 SID 生成式召回中"每物品 L 级 token 占满上下文窗口、可容纳历史被压缩 L 倍"的痛点，PinGER 提出非对称注意力掩码：交错排列 SID 与稠密 token，后续物品只 attend 稠密 token，使训练时每个 SID 位置都受监督、服务时每物品仅需一个 token 且计算等价。生成侧通过目标条件输出、强化学习与前缀多样性惩罚实现面向特定 surface 的可控、多样候选；服务侧配套 wide-beam 生成栈、合法标识符约束解码与 host-local 索引解析。Related Pins 线上 A/B 中，新 Pin saves +3.60%、整体 saves +0.62%，端到端延迟反降 0.7% 并消除被替代的最近邻检索成本。属于 SID 生成式召回的扎实工程优化而非范式突破，但"训练多监督、服务单 token"的掩码技巧对任何做生成式召回的团队都极具借鉴价值。

2. SLIDE: Search-to-List Item Distillation for Single-Rollout Generative Retrieval

🔗 原文： https://arxiv.org/abs/2610.34764

🏷️ 来源： 🏭 工业界 | Alibaba

⭐ 评分： ⭐⭐⭐⭐ (4/5)

🎯 推荐理由： 工业界生成式检索蒸馏框架，单次贪心解码生成列表，淘宝搜索验证有效。

📝 摘要： 生成式检索通常依赖 item 级 beam search，跨物品依赖未被建模且难以直接优化列表级目标；而直接训练列表生成模型做贪心解码又显著劣于 beam search，作者归因于 beam search 探索的更大搜索空间与稀疏正样本导致的位置偏置（后位监督不足）。SLIDE 提出 search-to-list 蒸馏：教师离线做 item 级 beam search 获取高质量候选（提供超越稀疏行为标签的转化相关监督），将其 SID 按 beam 分数拼接为列表级蒸馏目标，把分散搜索路径上的候选转化为单条自回归轨迹内的顺序生成目标；学生单次贪心即可产出 Top-K，同时解耦教师规模与线上部署。FORGE 与淘宝搜索实验显示单贪心解码下检索质量大幅提升，强教师下可超越 beam search 参考，补充 RL 实验进一步验证列表级生成有效性。对生成式召回在线化（降延迟、免 beam search）有直接工程参考价值。

3. Octen-WebGR: Scaling Generative Retrieval to 200 Million Web Pages

🔗 原文： https://arxiv.org/abs/2610.35256

🏷️ 来源： 🏭 工业界 | Octen

⭐ 评分： ⭐⭐⭐⭐ (4/5)

🎯 推荐理由： 生成式检索首次落地 2 亿网页，单 GPU 运行，导航搜索 top-1 达 59.6%，揭示查询侧与页面侧泛化互补。

📝 摘要： 导航搜索需在数亿网页中定位单一目标页，点击表对新问法泛化差、嵌入检索对导航目标排序弱。Octen-WebGR 把网页存进语言模型参数：给定 query 自回归生成两 token 语义标识符并约束到真实 URL 表，4B 模型索引 2.01 亿网页，在训练后一个月的真实导航流量上评估。关键发现是生成式检索擅长"新问法找熟悉页面"（未见 query 命中高交互页 top-1 30.9% vs 稠密检索 17.2%），而嵌入检索在冷门页面仍占优，二者在 query 侧与 page 侧泛化互补；整体导航流量 top-1 达 59.6%（稠密检索 46.5%，前沿 LLM 记忆回答仅 37.5% 且成本高 40 倍）。4B 模型单 GPU 10GB 内存运行，对比精确稠密检索 412GB；缩放实验表明模型规模随索引亚线性增长、检索更受页面曝光度而非模型容量约束。局限在于仅验证导航型查询、未报告点击/转化等业务 A/B 指标。

4. Unified Heterogeneous Feature Interaction via Effective-Rank Scaling for Recommender Systems

🔗 原文： https://arxiv.org/abs/2610.35318

🏷️ 来源： 🤝 产学合作 | Alibaba, Renmin University of China, Chinese Academy of Sciences

⭐ 评分： ⭐⭐⭐⭐ (4/5)

🎯 推荐理由： 阿里提出 HiRank 统一框架，融合序列注意力与异构特征交互，线上订单/用户提升 2.27%。

📝 摘要： 工业精排需在严格服务约束下同时建模异构特征交互、长期行为与多场景依赖，但现有架构将序列与非序列特征分模块处理、限制双向信息交换，且序列/非序列信号的有效秩（eRank）不同，直接套用同质自注意力效率低下，共享表示还会引发场景间负迁移。HiRank 在统一 backbone 中融合门控序列注意力与异构特征交互实现双向融合，用场景感知聚合把异构低阶 token 压缩为紧凑表示，再经不同学习投影生成场景感知复合 token（互补全局视角、更均匀信息密度）以支撑更有效的高阶自注意力。工业规模数据集上性能随参数量良性 scaling 并稳定优于强基线，线上 A/B 订单/用户 +2.27%。属于对现有特征交互与序列建模的架构整合改进，非开创性，但对多场景统一精排的落地设计有较高参考价值。

5. CRIM: Composable and Reusable Item Memory for Efficient Personalized Retrieval

🔗 原文： https://arxiv.org/abs/2610.35323

🏷️ 来源： 🤝 产学合作 | Alibaba, Tsinghua

⭐ 评分： ⭐⭐⭐⭐ (4/5)

🎯 推荐理由： 解耦物品语义编码与请求建模，缓存复用物品记忆，大幅降低 LLM 个性化检索推理成本。

📝 摘要： LLM 个性化检索中，交互历史增长拉长请求输入、同一物品文本被反复编码，训练与推理成本高企。CRIM 将物品级语义编码与请求级历史建模解耦：少量可学习 summary token 把每个物品压缩为紧凑连续记忆，段级读出 token（REC token）在交互历史内引入预测监督；这些记忆与用户、query 无关，可跨请求复用，推理时按交互顺序组合缓存记忆并可选注入 query 生成个性化检索表示。训练侧提出缓存+采样重编码联合机制：每请求仅重编码少量历史物品即可联合优化物品与请求编码器，配合周期性缓存刷新保持一致性。MovieLens-1M、Qilin 及自建 LazSeq 上达到同骨干规模 SOTA 检索性能且推理成本显著降低，并有单卡延迟与成本分析。创新在于记忆复用与联合训练的工程化设计，属对 LLM 推荐效率问题的有效改进，但未见线上 A/B。
