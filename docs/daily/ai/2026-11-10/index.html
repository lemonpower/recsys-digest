OpenAI 与 Anthropic 同日宣称自家模型挑战 25 年的 Exponential Time Hypothesis，学界三人组接管独立评审 ｜ 「AI 产出理论成果后，学术共同体如何验证」的现场样本

OpenAI 称其确定性算法可在次指数时间内精确计数 k-CNF 公式的可满足赋值；Anthropic 给出 3-SAT 次指数算法、把 Claude 列为作者，并用 Lean 4 生成可机器校验的形式化证明。两家都主动划边界——Anthropic 强调只是渐近意义、不影响实际求解，OpenAI 否认推出一般 NP 问题有次指数算法。真正值得读的是学界反应：Paturi 称意外但三十年基于该假设的研究不会消失，MIT 的 Ryan Williams 称自己作为长期怀疑者「被平反」，Impagliazzo 直言更希望是人类研究者能解释推理过程；三人正共同组织独立评审。与「PSI 用 Anthropic 未公开模型证明量子猜想」同属「AI 自动发现 + Lean 形式化验证」母题，但主体、猜想、公司均不同。

「你不需要长上下文」：NVIDIA 团队实测三种上下文管理范式，Qwen 3 Coder Next 窗口 256K→16K 解码吞吐提升 7 倍 ｜ 直接挑战「长上下文是刚需」的主流假设

论文指出前沿模型后段 token 生成成本可达前段 7 倍，因此 agent 未必需要长上下文。对比全量累积（FHA）、到阈值压缩（EoCC）、每步只带状态交接（SAC）三种方式，在六类长程任务上 Claude Opus 4.5 与 GPT 5.6 Sol 的 22 组配置中最多只有 5 组比全量历史基线掉超过 2 个百分点；长输入任务改为把文档当文件、让 agent 检索并只读有界片段。工程侧最硬的数字是 H100 + vLLM 上把窗口从 256K 降到 16K，解码吞吐提升 7 倍。关键细节：好的 compaction 是「面向未来的交接简报」（任务、进度、计划、完成条件、产物指针），而不是对历史的泛泛总结，并据此提出 semantic state space models 概念。注意 7x 是 serving 吞吐而非任务端到端加速。

来源：alphaxiv.org

OpenAI 公开研究基础设施「总控室」Control Room：每个 workload 必须先绑已批准 safety case 才拿到 job_id，推理引擎每次采样前查授权，35 秒内停止出 token ｜ 工业级模型 kill switch 的架构底稿

所有研究侧推理负载（RL 实验、评测、大规模采样、数据处理）统一登记，推理引擎在每次采样前向 Control Room 询问该 job 是否仍被授权，一旦被停就拒绝出 token。设计上强调「Control Room 自己挂了也要能停」，并与 misalignment 监测系统联动。对做 agentic 训练、需要给模型加运行时熔断的团队，这是少见的、把「授权—采样—中断」做成三段式硬约束的一手参考；job_id 授权模式即便在中小规模也能直接借用。

来源：openai.com

Amazon × Hugging Face 发布 HOPE：二阶专家剪枝，50% 剪枝率下平均排名最优、agentic coding 高次优方法最多 +6.1% ｜ MoE 部署降本从「独立打分」转向「建模专家协作组」
