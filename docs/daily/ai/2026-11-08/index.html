📊 今日概览

今日最值得关注的是资本与政治的双重转向：Anthropic 拟 11 月中旬登陆纳斯达克，但估值预期从 2 万亿美元下调至 1–1.5 万亿；中期选举中 41 项数据中心公投 40 项被否决，费城半导体指数单日暴跌 12.2%，Alphabet 单季 capex 已达经营现金流 121%。模型侧，Thinking Machines Lab 发布 594B 总参 / 17B 激活的 Inkling 2 Small，先闭源安全测试、下周以 Apache 2.0 开放权重，Bridgewater 用其微调 Qwen3-235B 在金融任务上以 1/14 成本胜过 GPT-5.5。工程侧，一份对 10,659 个公开 MCP 配置的扫描显示 67% 未锁版本、941 个仍指向已归档 server，MCP 供应链风险首次被大规模实证。

  • 开放权重走"先测后放"：Thinking Machines 的 Inkling 2 Small 先闭源安全测试再 Apache 2.0 放权重，叠加 Bridgewater 微调案例，企业"开源基座 + 托管微调"路径成型
  • MCP 从协议走向运维：67% 配置未锁版本、941 个指向归档 server、152 个含疑似真实 token，供应链治理与工具 schema 版本化成为生产落地关键

Thinking Machines Lab 发布 Inkling 2 Small：594B 总参 / 17B 激活 MoE，先闭源安全测试、下周 Apache 2.0 开放权重 ｜ Murati 团队首个开放权重模型 + 传闻 5 亿美元新融资

支持图像输入与可变推理强度，Artificial Analysis Intelligence Index 得 31 分，官方归因于更高效预训练 + 一次大规模统一 RL。策略值得注意：不再直接开源，而是先闭源做外部安全测试、下周再以 Apache 2.0 放出权重，首发落在自家微调服务 Tinker 上。落地案例里最硬的是 Bridgewater 用 Tinker 微调 Qwen3-235B 做金融新闻与利率信号筛选，六项任务准确率 84.66% vs GPT-5.5 的 78.2%、错误率低约 30%、推理成本约 1/14——这是「企业拿开源基座 + 托管微调打垂直任务」目前最具体的一组数字。同时传闻公司接近完成 Accel 领投的 5 亿美元融资。

10659 个公开 MCP 配置全量扫描：67% 的 server 未锁版本，941 个仍指向已归档的官方 reference server ｜ MCP 供应链风险的第一份大规模实证

作者抓取 GitHub 上 10,659 个公开 MCP 配置文件（共 32,223 个 server），逐一比对 npm/PyPI 版本与 OSV 漏洞库。除「三分之二未 pin 版本」外，还有几个更刺眼的数字：941 个文件仍指向 2025 年 5 月已归档的官方 reference server（仅 server-github 就 580 个，不再有安全修复）、638 个指向不存在的包（可被抢注投毒）、152 个文件含疑似真实 API token、15 个跑在被 npm 替换为恶意占位符的包名上，仅 48% 文件无需整改。文中给出一行修复法（args 里写死 `@playwright/mcp@0.0.84`）——今天就能拿自己的配置去对一遍。

NVIDIA FOX 参考架构：manager agent + 专家 agent 编排工厂运维，把「哪些决策需人工签核」做成可配置项 ｜ 工业 agent 落地的 harness 与权限设计样本

Factory Operations Blueprint 的编排方式是 manager agent 调度专家 agent——视觉检测调 Cosmos、根因分析调 Kumo Anomaly、车队管理用 Isaac Sim/ROS 2，默认 harness 为 NemoClaw、执行隔离用 OpenShell，跑 Nemotron 模型。最有借鉴价值的设计是把「哪些决策需人工签核」做成工厂可配置项而非产品变体，Siemens Erlangen 站点称订单规划 agent 降本约 20%。属二手拼贴、缺一手技术细节，但多 agent 编排 + 人工签核边界这套骨架对做企业 agent 的人可直接借用。

MCP 上生产的两份 checklist：凭证按工具做最小 OAuth scope、工具 schema 永不原地改（改用 `_v2` 命名版本化） ｜ 规范写得好，运维面全是坑

作者把 MCP 从「协议规范」和「生产运行」切开：开发环境能跑的工具在生产 API 上因认证边界静默失败；client/server 版本不匹配表现为晦涩的 JSON-RPC 错误；没有 timeout 时单个慢工具会阻塞整个 agent loop；缺少标准 tracing 格式导致 15 工具工作流调试全靠猜。两条可复用约定：凭证从 secrets manager 启动时拉短时 token 并按工具做最小 OAuth scope，避免 .env/日志/镜像泄漏；工具 schema 永不原地修改，改用 `search_documents_v2` 式命名版本化，因为 LLM 消费者没有版本头。另一篇从 SDK 视角补了同一主题的另一半：v2 TypeScript SDK 已把 transport/discovery/validation 全包，真正决定成败的是 tool 名称、description、参数 `.describe()` 和错误信息——因为读者是运行时读 JSON Schema 的模型而非看文档的开发者；并提醒 stdio 模式下误用 `console.log` 会破坏 JSON-RPC 流。
