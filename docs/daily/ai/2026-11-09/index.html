📊 今日概览

今日最重的事件是 NVIDIA 的治理黑天鹅：董事会启动独立调查，CEO 黄仁勋承认与疑似中国情报人员 Alice Huang 的私情，国会要求其 11 月 18 日赴听证，而 Megaspeed 已成为 NVIDIA 最大买家之一（采购约 48 亿美元设备）。资本侧同样热闹，生成媒体推理平台 Fal 以 160 亿美元估值完成 13 亿美元 F 轮，7 个月估值翻倍、年化营收从 3 月的 4 亿冲到 8 亿；agent 运维赛道 Traversal 以 10 亿美元估值融资 1.2 亿美元。技术侧，NVIDIA 开源 Auto Ontology 给 text-to-SQL agent 补业务本体层，Stanford CS146S 课程因 agent 一个 prompt 秒掉往年作业而被迫重构，Andrew Carr 则串起「蒸馏带隐形特质」「RLVR 只提升采样不扩能力」两篇论文。

🔧 工具与产品

  • NVIDIA 开源 Auto Ontology，给 text-to-SQL agent 补一层业务本体 - 写 SQL 前先把业务概念映射到具体列：术语（如 revenue 存在哪一列）、SQL 属性（利润率、滚动合计等复用表达式）、表间关系（含桥接表）。本体从数据库元数据自动起草、人工审核，存 Postgres、向量用 pgvector。支持 Postgres、Snowflake、Databricks、DuckDB 等 10 种引擎，默认跑 Nemotron、也可接任意 OpenAI 兼容端点，Apache 2.0。数据答不了的问题会直接说明，不编数字 @akshay_pachaar（AI 教育博主 / DailyDoseOfDS 创始人）
  • Specialist：开源机器人操纵全栈，硬件到部署一套齐 - Qiayuan Liao 与 t_k_233 把夹爪设计、数据流水线、训练与部署代码全部开放，对标 GeneralistAI 的夹爪方案。原本打算当"周末项目"做，实际每项设计取舍都写进了文档 @qiayuanliao（UC Berkeley 机器人研究者）
  • Kling 4.0 用一支能量饮料广告演示产品细节与角色一致性 - 创作者 leedain_leader_in 展示工作流从"剪辑"转向"导演"：模型负责产品细节、角色一致性和自然对白 @Kling_ai（快手视频生成模型）

⚙️ 技术实践

  • Together AI 优化 StepFun 服务栈，吞吐提升 3 倍以上 - 对着 TTFT 与 TPS 目标逐项调 MoE 路由、调度、kernel、spec decode 和稀疏注意力，每改一处先跑基准再进下一步，agent 参与搜索 @togethercompute（模型推理服务商）
  • 腾讯与微信发布 WeLM-Image：MoE 31.7B 总参 / 5.4B 激活的统一图像生成模型 - 定位"迈向视觉智能"的统一图像生成，论文已放出 @SD_Tutorial（AI 绘画内容博主）
  • Andrew Carr 串起两篇论文：蒸馏会带隐形特质，RLVR 只提升采样不扩能力 - Subliminal Learning 显示教师模型只用数字序列生成数据，学生也能学到"喜欢猫头鹰"或"对齐偏差"等特质，过滤数据也挡不住。另一篇称 RLVR 模型在 k=1 时超过基座，但 k 大时基座 pass@k 更高——RL 让模型更会采样已有答案，没扩大能解的题 @andrew_n_carr（AI 研究者 / 博客作者）

Stanford CS146S 课程被现实改写：去年九次作业今年被一个 prompt 秒掉，改成给开源项目提 patch 由 maintainer 亲自 review ｜ AI 原生工程教育的现场迭代记录

Mihail Eric（Monaco AI 负责人）复盘教学设计：agent 能写功能，但判断「维护者要不要、为什么这样写、会破坏什么」仍是人的活。生产侧两条硬结论：code review 工具买 Devin、agent workspace 自己造（buy to learn, build to keep）；内部系统 Hal 对工程师输出可 review 的 PR、对销售输出可讲给客户的解释，同一后端两种出口。还点出 agent 看不到「六个月前这个改动为什么被拒」的历史决策，由此预测 open-source repo 将变成 agent-run software factory。附 Geoffrey Litt 的 explain-diff skill 可直接用在下一个 PR 上。

用 Rust 从零重写 Karpathy 的 run.c：手搓 prefix caching + 三线程 + FIFO 调度 + continuous batching，CPU 上实测 4.27x ｜ 不啃 vLLM 源码也能建立推理服务 mental model 的工程笔记

从单请求 HTTP 服务起步，逐步加：prefix caching 按 token chunk 哈希、带父哈希链回溯最长可复用前缀（实测 11 个 prompt token 复用 8 个）；消息传递 + HTTP listener/模型执行/回复三线程架构；FIFO + active/waiting 池的请求调度器；最后把 active 池扩到 batch size 实现 continuous batching（4 请求 × 16 步：44.5 → 189.6 tokens/s）。规模是教学级单机 CPU demo，无生产级 eviction、chunked prefill、streaming，但每一步都在回答「vLLM 的这个机制到底在解决什么问题」，是少见的从零搭推理服务第一人称记录。

来源：matthewtejo.substack.com

P-H3-Image 实测：Pruna AI 从 MiniMax-H3 视频模型蒸馏出的图像模型，txt2img 不如 Krea 2 / MOSS-Image，但 Edit 能力持平或超过 Qwen-Image-2.1 ｜ 20B DiT + Qwen3-VL-4B TE + MiniMax-H3 VAE 的完整参数对照

架构为 20B DiT + Qwen3-VL-4B 文本编码器 + MiniMax-H3 VAE，最轻配置 21GB，支持 8MP/4K 优化（1MP 下发挥不出实力）。文中给出与 FLUX.2 klein 9B、Anima、Krea 2、Qwen-Image-2.1、FLUX 3 Image klein、MOSS-Image、MiniMax-H3 的 DiT/TE/VAE 参数对照表，以及 ComfyUI 环境搭建与 prompt 指南。对想试新图像编辑模型的人有直接参考价值；注意这是 LoRA 蒸馏派生模型而非全新基础模型，且作者聚焦 2D 编辑与 NSFW 用途，受众偏窄。

Claude Code 2.1.277 支持 AGENTS.md，但只是「无 CLAUDE.md 时的 fallback」而非合并 ｜ 跨工具共享 agent 指令的正确姿势是 `@AGENTS.md` import

作者拆解 CLAUDE.md 的树状加载机制（根目录→工作目录逐层拼接、子目录按需加载、CLAUDE.local.md 后置），指出跑过 `/init` 的仓库 fallback 永远不会触发，所以别指望它自动生效。正确做法是在 CLAUDE.md 里写 `@AGENTS.md` import。另提示该开关只能在 `/config` 的 Project instructions 里改，无 settings.json 键、无环境变量，Bedrock/Vertex/Foundry 尚未支持，官方 memory 文档尚未更新。实操结论一条：用 import，别用 fallback。

来源：dev.to

自建个人 agent benchmark：用最终状态断言做确定性评分、拒绝 LLM judge、统一 JSON 工具协议把 tool-call 可靠性本身变成可测信号 ｜ 「公开 leaderboard 测的是别人的任务」

作者主张公开榜单测的是别人的任务、别人的 rubric，对「这个模型能否可靠完成我的活」无用。设计取舍值得抄：每个任务用最终状态断言评分而非 LLM judge；所有模型统一走文本 JSON 工具协议，从而把 tool-call 可靠性本身变成可测维度；任务按 file_ops / api_orchestration / trading / debugging / data_wrangling / obsidian 分类，本地 Ollama 与前沿模型同场跑分，像给「AI 员工」做绩效评估一样决定留用与分工。适合想给自己工作流做模型选型的人参考其设计逻辑。

来源：dev.to

Traversal 以 10 亿美元估值完成 1.2 亿美元融资：用 agent 自动排查软件故障、定位根因 ｜ 「agent 从写代码转向运维代码」的赛道信号

Kleiner Perkins、Redpoint、Khosla 联合领投，Sequoia、Battery 跟投，客户包括 American Express、Pepsi、Blackstone。切中的痛点是：AI 编码工具让代码产出速度暴涨，可观测性与维护难度同步上升，故障诊断成为新瓶颈。与 Cloudflare Q3 财报里「AI 公司签 1100 万美元 Workers 合同支撑数千万个 AI 生成应用」互为印证——agent 规模化后，运维侧与边缘部署侧同时成为刚需。两条都只是财务/融资侧证据，缺产品技术细节。
