⚙️ 技术实践

  • Omar Khattab 组论文：组合式 harness 比标准编码 Agent 的 RL 算力回报更高 - 论文《LM Harnesses are Compositional Generalizers》把 harness（模型外层的调用编排层）当作组合泛化器，挑出三项能共同起作用的抽象：上下文卸载、程序化工具调用、子 Agent 调用。关键做法是把每条轨迹压成局部同分布（LID），也就是让每一次单独调用都落在训练分布内，从而能泛化到更长的任务、更多样的策略和更深的递归。对 rollout 极长的任务，甚至可以用纯合成任务、假工具调用与假子 Agent 做「代理 harness 训练」，只训单次调用。作者反对「强模型会把 harness 吸收掉」的看法，并放出论文、日志、代码与数据 @a1zhang（论文一作）｜@lateinteraction（Omar Khattab，MIT 教授 / DSPy 作者）
  • Gemini 4 Neon 在 ParseBench-2 表格解析与包围盒精度全面第一，成本 6.2 美分/页 - 评测由 LlamaIndex 的 ParseBench-2 完成，对比对象含 Opus 5.5 与 GPT-6.2 Sol，Gemini 4 Neon 用的是低思考模式。复杂表格解析与包围盒精度都是最优。Jerry Liu 提示价格偏高，只建议留给最重的负载 @jerryjliu0（Jerry Liu，LlamaIndex 创始人）

OpenAI 首次系统披露「对抗性蒸馏」攻防：推理链提取攻击成功率从 54.0% 压到 0.2% ｜ 前沿模型 IP 与安全护栏的一手底稿

攻击者用前沿模型输出（尤其是 chain-of-thought 推理链）训练自家模型，从而继承能力却绕开安全护栏，在网络安全、生物等 dual-use 领域风险最大。文章拆解多层防御——对抗测试、模型训练、分类器、API 级防护，加上对协同提取行为的调查与打击，并给出量化进展：在自适应自动化红队评测下，GPT-6.2 Astra 的推理链提取攻击成功率从 54.0% 降到 0.2%。对做模型安全、API 防护、数据授权与合规的团队，这是目前最完整的一份官方防御体系说明。

来源：news.mit.edu

AWS 把分布式 KV caching 封装成 Agent Skill：coding agent 几轮对话内完成评估与部署，官方称自托管推理成本降 40%、TTFT 降 80% ｜ 长上下文自托管推理的可照搬落地底稿

工作流值得记：先用只读 describe-instances 数 EFA 网卡做 fit check，再用 KVTrace 基于你自己的模型与流量估算收益（短 prompt 下加载 KV 可能比重算更慢，存在 cutover 点），收益不覆盖成本就主动叫停；随后给现有 vLLM/SGLang 引擎加 LMCache connector，统一各推理服务器的 KV ID 机制（hash+seed）与数据类型避免 key mismatch，上生产前清空本地层并验证两次 cache-loaded 输出一致——因为布局不匹配会出现「命中计数健康但答案错误」。对做长上下文 agent / 法律 / 代码助手自托管推理的团队，这是完整可复用的工程底稿。

来源：aws.amazon.com

World Labs 把 Atlas 世界模型开放给开发者：自托管 API + 网页工具，720p 首帧 $0.04、后续帧 $0.008，视图转 splat $5 ｜ 世界模型商业化重心从机器人仿真转向内容生产

底层是 from scratch 预训练的多模态自回归 diffusion transformer，把每张图与深度图绑定到具体相机位姿，从而多视角一致渲染。Rapidata 公开榜上 19 个视频/世界模型中相机运动指令跟随第一，人类对战胜率 76.7%；自测 3D 重建误差比次优 Pi3X 低约 12%，但无 model card、无论文、无第三方复现。与 Genie 4、GWM Worlds 2 这类只能看不能用的交互视频相比，Atlas 的优势是「有价目表 + 有导出按钮」，输出可直接进游戏引擎和 Blender。值得注意的转向：新开发者文档已不再提机器人，而 AMD 82 亿美元全股票收购已于 11/16 交割、李飞飞任 AMD 首席科学家。

来源：charonhub.deeplearning.ai

Latent Space 系统梳理 formal verification 如何成为对抗 AI「slop」的新武器：cvc5 每天被 Amazon Kiro 调用数十亿次，横评 Harmonic / Theorem / Axiom Math / &Truth 四家路线 ｜ 理解「agent 输出可信性」的入门地图

核心对比是：AI coding agent 所谓的「验证」只是跑测试、自我批判、模型互评，永远无法确认「是否还有漏网问题」；而基于 SMT solver 与 Lean proof assistant 的形式化验证能给出数学意义上的完备性。文中借 Stanford 教授、cvc5 作者 Clark Barrett 解释 &Truth 的「verification machine」野心：读任意语言代码、证明其满足精确需求。对关心 agent 输出可信性、代码生成质量兜底的人，这是 2026 核心议题的一份赛道地图。

来源：latent.space

Sean Goedecke 用一组自测数据拆掉「缓存模型输出」的直觉：agent 输出 token 中 50% 是 reasoning、44% 是 tool call，可见输出只占 6% ｜ 纠正 agent 成本优化直觉的短小底稿

即便把可见输出里的重复内容砍掉三分之二（极乐观估计），按 Amdahl 定律也只省下总输出 token 的 4%。他进一步指出模型在内部思维链里基本不会重复自己，所以「让模型引用而非复述」只优化了最不值钱的那一段。真正有效的方向是省 reasoning 与 tool call 的 token。对做 agent 成本治理、上下文工程的人，这是一份反直觉、有量化、可迁移的纠正材料。

来源：seangoedecke.com

「Represented but misread」：post-training 改的是模型「怎么读出」已有表征，而非表征本身，平均把回答敏感度拉低 Δd'=-0.34 ｜ 输出错 ≠ 没学会的诊断框架

实验在六个开源 base 模型及其 post-trained 版本上做人类/AI 文本判别：线性 probe 和 n-gram 分类器能很好区分，模型答案却不行、部分甚至把顺序判反。分阶段 checkpoint 与 model stitching 显示变化发生在 SFT 阶段、集中在文本之后位置的早期层，即模型学了一套新的决策策略而非表征被破坏。工程建议很实用：答案重要时同时测 base、post-trained 和外部简单分类器三层，若简单分类器看得到信号而 chat 模型看不到，就别再死磕 prompt，按 readout 问题处理，用小型监督数据定向纠偏并跨域严测。

来源：kenashe.ai ｜ arxivsignals.io ｜ arxiv.org

Why the Agent Era Needs a New Operating System | DHH

📍 来源：a16z Show | ⭐ 4/5 | 🏷️ Agent, Open Source, Product | ⏱️ 00:53:25

DHH 与 a16z GP 讨论为何 agent 时代需要新操作系统，介绍其打造的 Omarchy——一个 agent-first 的 Linux 发行版，用户可通过自然语言修改系统。核心观点：命令行、配置文件、详细报错这些曾让 Linux 令人生畏的特性，反而使其特别适合 agent；软件开发变便宜后，平台锁定被挑战，而 taste、craft 和对最后 2% 的执着更重要。还谈及小团队拥有千人产能、开源模型、前沿竞争及黑客/demo/匿名互联网文化回归。对 Agent 从业者的价值在于系统层与交互范式的判断。

💡 推荐理由： DHH 是 37signals 创始人、Rails 作者，属有代表性 AI 应用/工具创始人（A 级）；深度讨论 agent-first OS、开源模型与前沿竞争，一手判断多；但非前沿实验室研究员，技术细节偏理念。
