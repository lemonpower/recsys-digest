⚙️ 技术实践

  • 蚂蚁在 8×H20-3e 上做 PD 分离，DeepSeek-V4.1-Flash 端到端从 13.63 秒降到 4.70 秒 - 输出吞吐为 TP4 的 2.91 倍（64K 提示），TTFT 从 12.04 秒降到 1.89 秒，代价是 TPOT 从 3.20 升到 5.62 毫秒。单台 4 卡混部 worker 的 E2E 从 18.62 秒降到 7.96 秒。博客把七项改动逐条叠加、逐项测量 @lmsysorg（SGLang 团队）｜另两篇 KV 优化：NVFP4-MLA 用 FP4 统一 MLA 的 KV cache 存储与注意力计算 @MuzafferKal_（研究者）；Vulkan 用光追加速器给 FlashAttention 做 KV 过滤 @never_released（社区开发者）
  • Weaviate 按 agent 视角重写文档，正确示例命中率 50%→100% - 先测 agent 读文档时看到什么、得出什么结论，再针对性改写。达成正确方案所需轮次从 23 降到 6，单页加载 token 降约 20% @weaviate_io（Weaviate，向量数据库公司）

  • 外层模型只读权重就能给 Qwen3.5-0.8B 去拒答 - Varun Gangal（Patronus AI 研究者）等测试无梯度、无训练的权重编辑：原模型拒答率 0.80，Arditi 方法可压到 0.07。零样本下 Inkling-2-Small 降到 0.57，Opus 5.5 为 0.55，GLM 5.3 为 0.74。给 10 次前向后 Inkling-2-Small 到 0.19，Opus 5.5 到 0.17。零样本模型是靠输出嵌入构造"有害词 vs 普通词"方向再投影出去，Opus 则先定位推动拒答的晚期 MLP 神经元，再反推方向，把"有害判断"与"做不到"两根轴分别摘掉 @VarunGangal
  • JEPA 世界模型两条进展：会规划点云、会推断意外 - JEPA4R（Hao Tang，研究者）在点云潜空间做规划并解码 4D 点云，OGBench Cube-Single 得 78.4%，最好 2D JEPA 为 46.8%，真机零样本可用 @HaoTang_ai。Randall Balestriero（布朗大学研究者）与 Yann LeCun 等给 JEPA 加上对意外事件的推理，可推断"若换一个动作会怎样"，并给出可证明保证 @randall_balestr

BMW 集团公开数百个 agent、12,500 名开发者规模的治理底稿：治理规则外置到 MCP gateway 与 agent registry，信任按「步骤」而非「agent」分级 ｜ 企业级 agent 规模化最完整的一份实践

核心主张是「让 agent 从第一天就能协作」——认证、授权、限流、内容过滤不写进各 agent 代码库，而是外置到集成层，从而在框架迁移、模型替换、团队重组后依然生效。最有迁移价值的是 per-step 而非 per-agent 的信任分级：Level 0 人类在环、Level 1 人类在环上异步复核、Level 2 护栏内自主，且护栏用确定性代码在 CI/CD 中强制执行，agent 与其 prompt 无法绕过。另强调从第一天起用真实 ground-truth 数据集做持续评测，而非合成 prompt。对推动企业内 agent 规模化的团队，这是目前最完整的一份可照搬治理底稿。

来源：aws.amazon.com

AWS 把 AgentCore payments 接到 Marketplace：agent 遇 402 后凭签名报价换 payment token 重试，费用直接落 AWS 账单 ｜ agent 自主采购走向可审计生产链路

链路是：卖家返回 402 Payment Required → agent 把签名报价转给 AgentCore payments → 校验会话预算后换回 payment token 重试请求，费用以 USD 落在开发者 AWS 账单上，不需要稳定币钱包也不需要 API key。配套上线 Gateway 的 Marketplace connector 用于发现卖家与端点，policy 可设消费上限与白名单卖家，交易在 CloudTrail / Cost Explorer 可审计，企业 Private Marketplace 规则同样生效。文中给出研究 agent 现场发现 Tavily 搜索工具、单次付费、带引用作答的完整 walkthrough 与 GitHub sample。这是「agent 自主采购」从 demo 走向企业可审计链路的一手底稿。

来源：aws.amazon.com

OpenAI 首次系统披露 Performance Factory：Codex 驱动的自动化性能工程，把「告警到恢复」整条链路交给 agent ｜ agentic workflow 从写代码扩到运维回归

CMU 博客「可证明安全」下篇：即便 agent 理性、合作、算力无限，多 agent 多目标达成一致的最坏通信成本仍随目标数与 agent 数增长；reward hacking 在有限样本下不可避免 ｜ 对齐的理论下界，不是工程能绕过的

把 AAAI 2026 Oral 论文的结论讲成可读叙事：更聪明无法消除对齐障碍，因为要求更精确一致就要更高通信成本。进一步，当期望只能从有限样本估计时，训练数据覆盖的空白会让有害行为看起来有奖励，因此应把精力放在安全关键的状态切片而非均匀覆盖。文章随后梳理 corrigibility 谱系——Soares 的 off-switch game、Hadfield-Menell 的偏好不确定性促成服从、Garber 2025 的证据不对称反而使规避关机最优、Armstrong 的 utility indifference 与 safe interruptibility 各自缺口。核心洞见值得记住：帮助 agent 完成任务的预测能力，同样能帮它绕过人类干预。

来源：blog.ml.cmu.edu

阿里 MARS 技术报告：用微调 Qwen3-0.6B 的 near-line agent 为每个用户生成七维级联配置，淘宝五场景两周 A/B、最大场景 V2P +5.22% / GMV +7.34%，平均服务延迟反降 12ms ｜ 推荐系统 agentic 化的「LLM 只做编排、不碰在线链路」范式

把召回-粗排-精排-重排的 pipeline 级决策（通道激活、配额、模型选择、融合权重、重排设置）交给 agent，关键工程点是异步解耦：配置先校验、缓存再被消费，级联链路从不等待 LLM 推理，配 schema 校验、fallback 与 kill switch 兜底。策略训练三阶段值得记：置信度感知 SFT 蒸馏 → FAPO 用 ActionMask 学动作偏好 → GRPO 在 sandbox 回放中精调，探索动作不触达线上流量。约 20% 请求走 Minimal 轻量模式。对做推荐系统 agentic 落地的人，这套「LLM 在旁路、在线链路零等待」的架构比模型本身更值得抄。
