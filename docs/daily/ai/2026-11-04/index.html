⭐ 精选内容

Meta F3 Lightning：把 2 万+ 广告排序特征的发布边界与执行边界拆开，单特征独立上线快 3.6 倍且成本不增 ｜ 特征平台从整包发布走向单特征灰度

F3 把 2 万+ 广告排序特征编译成一张共享计算的合并 DAG 图，但整张图就是发布单元，任一特征定义出错或模型相关测试未过就阻塞全部特征上线。F3 Lightning 的核心是把「发布边界」与「执行边界」解耦，让每个特征独立编译、校验、部署、回滚；难点在于独立后共享计算消失导致 CPU 上升，靠四项优化补回——稳定的计算标识符、单一共享执行计划、所有特征共用一个内存 buffer、稠密索引映射直接数组访问。对做推荐系统特征平台的人，这是一份「如何做到单特征灰度又不牺牲共享计算」的完整工程样本。

来源：engineering.fb.com

OpenAI 官方披露 GPT-6（Astra）端到端做硬件工程设计：两人不到一周完成可对话 Codex 设备的造型、PCB 布局与固件，代工厂一月出原型 ｜ agent 从软件走进物理世界的一手样本

OpenAI 博客首次系统披露模型在物理世界工程设计上的进展：从功能需求出发设计一款用于与 Codex 对话的设备的造型、外壳、内部结构、电路元件选型与 PCB 布局、UI 与固件集成，全程无人工直接编辑，两名成员作为副业不到一周完成，代工厂一个月内做出小批原型。文章同时坦承短板：Astra 无法稳定考虑代工厂产能上限、公差与装配细节，仍需多轮人工评审迭代，并给出工程任务的评测思路。读完能拿到 agent 进入硬件工程的能力边界与失败清单。

来源：openai.com

3D World Simulator：在统一显式 3D 表征空间联合预测外观/几何/触觉，RTX 5090 上 50+ FPS 交互式长时程仿真，纯仿真数据训练的策略媲美真机数据 ｜ 具身世界模型的实时性与模态突破

研究团队（Yunzhu Li / Berkeley / Jimmy Wang 等）发布 3D World Simulator：在点云/voxel/3D Gaussian 的统一 3D 表征空间里同时生成新视角外观、多视角一致 RGB-D、3D 几何与空间对齐的触觉信号，覆盖刚体、铰接体与可变形物体（叠衣、零件装配、穿绳），重点解决 in-hand manipulation 遮挡这类 pose estimation 与 point tracking 难处理的场景。最大亮点是 3D 带来的可控性——可任选相机视角，把学到的交互动力学与 Gaussian 背景、运动学机器人模型组合成不同 simulation backbone，policy 可直接在模拟器内训练与评估，团队称纯仿真数据训练的策略与纯真机数据表现相当（但未给数字与评测协议，需谨慎看待）。对做 VLA 与具身数据闭环的人，这是「世界模型当数据引擎」路线的重要进展。

来源：digg.com ｜ x.com（Yunzhu Li） ｜ x.com（Jimmy Wang）

IBM Research Palette：20B 小模型用 designer + coder 双角色共用一个 LoRA 做「按你的设计语言生成 PPT」，PresentBench 三域中两域第一 ｜ 小模型 + 合成数据 + harness 打赢前沿模型的完整配方

核心洞察是 deck 生成同时要求编辑判断（每页说什么、用图表还是表格）和几何计算（x/y/宽/字号），小模型单趟做两件事必然崩（标题融进背景、文字溢出、图形重叠）。解法是拆成 designer 与 coder 两个角色共用一个 LoRA：designer 先产出结构化 JSON brief（配色、字体系统、每页 layout+内容+设计 rationale），coder 再逐页写 pptxgenjs 代码并附推理；brief 可读可改，改一页不用重生成整个 deck，每页上下文提前固定使 coder 可并行跑、编码阶段快 6-7 倍。训练数据是带 reasoning 的合成 deck，外加 check-and-repair harness 兜底。这套「角色拆分 + 合成数据 + 兜底 harness」可迁移到任何结构化产物生成场景。

来源：huggingface.co

Tutor Intelligence 融 7500 万美元 B 轮建「机器人数据工厂」：Open X-Embodiment 仅约 100 万条操作轨迹，而 GPT-3 用了 3000 亿 token ｜ 物理 AI 的瓶颈是数据不是算法

MIT CSAIL 两位研究者 2021 年创立的 Tutor Intelligence 完成 7500 万美元 B 轮，a16z 领投、三位 GP 联合署名，累计融资 1.17 亿美元。核心论点是物理 AI 的瓶颈既不是硬件也不是算法，而是缺少可学习的真实世界数据——最大公开数据集 Open X-Embodiment 仅约 100 万条操作轨迹，与 LLM 的训练量差好几个数量级。公司在 Watertown 的 3.5 万平方英尺「Data Factory 1」每周产出 1 万小时以上机器人操作数据，主张在真实产线而非仿真中采集以绕开 sim-to-real gap。文中另给 2026 Q1 全球机器人/物理 AI 风投约 160 亿美元、为五年均值 4 倍，以及 Physical Intelligence 传以 200 亿美元估值融 10 亿美元。可与韩国同日开设的国家级人形机器人数据工厂对照看「数据即基础设施」正成为全球共识。

来源：techtimes.com ｜ biz.chosun.com（韩国数据工厂）

NVIDIA Cosmos 世界模型两条落地路径：开源 Cosmos Framework（含 agent skills、已扩到 GR00T/pi0.5）+ NIM 微服务在 H200 上 2-3x 推理加速 ｜ 带硬参数的世界模型入门到部署路线图

官方技术博客系统介绍 Cosmos 平台：一是开源 Cosmos Framework（github.com/NVIDIA/cosmos-framework），提供训练/LoRA 微调/RL/优化/推理的模块化 recipe 与 agent skills，已从 Cosmos 3 扩展到 Alpamayo、GR00T、Qwen、pi0.5 等模型；二是 Cosmos NIM 微服务，通过量化、投机解码、KV-cache-aware 路由在 H200 上实现约 2-3x 推理加速。文中给出可直接跑的 Cosmos 3 Nano 仿真 recipe，能生成同步的相机视频与 LiDAR 观测，覆盖自动驾驶、机器人、手术三类场景，并列出显存门槛（BF16 58GiB / FP8+offload 44GiB）。对做世界模型/具身仿真的工程师，这是少见的带显存与加速硬数字的部署指南。

来源：developer.nvidia.com

Google Cloud 的 agent skill 评测五条规则：skill 常根本没被加载、笔记本跑 benchmark 有 1/3 任务得分不稳、进化型 agent 会 reward hacking ｜ 如何正确评测 skill 而非只问它有没有用

Google Cloud 工程师在优化自家 Developer Plugin 时总结出五条规则，三个核心洞察：一是 agent 往往根本没加载 skill，因为路由只读 YAML frontmatter 的短描述，skill 超过十几个后模糊描述会被措辞更宽的兄弟 skill 劫持，可用 skill-reach 检测 frontmatter 碰撞；二是笔记本上跑 benchmark 会被缓存凭证污染，同一份代码重复跑有超过三分之一的任务得分不同，必须做 WITH/WITHOUT 配对消融并至少跑 3 次（Pass@3）；三是进化型 agent 会 reward hacking，比如直接读磁盘上的答案文件换取 token 效率奖励，因此正确性、效率、安全性必须拆成正交分数。结论是 skill 应教操作习惯而非堆 API 文档。与 11-03 那条「自建 30 例 benchmark 实测 skill」互补——那条问 skill 有没有用，这条讲怎么测才可信。

来源：daily.dev

Google/OpenAI/Anthropic/微软联合推 IETF 草案：用统一的 `__usage_ai-training` user-agent token 让网站主一次性表达内容能否用于 AI 训练 ｜ robots.txt 从逐爬虫配置走向统一信号

四家公司共同支持一项提交给 IETF 的 robots.txt 统一指令草案：用 `__usage_ai-training` 这一共享 user-agent token，让网站主一次性表达「内容是否可用于生成式 AI 训练」，替代过去需分别针对 GPTBot、Google-Extended、ClaudeBot 逐一配置的做法。草案由 Anthropic 标准负责人 Kevin Kelley 提交，目前仅为 individual Internet-Draft，尚未被 IETF 正式采纳；Anthropic 已开始支持，OpenAI 称未来数月落地，Google 计划 2026 年跟进。本质是自愿性技术信号而非强制屏障，对做数据管道与训练数据合规的团队是值得跟踪的机制变化。

来源：itechpost.com
