📊 今日概览

今日最重磅的是 Mistral Large 4（Le Chonk）正式开放权重：1T 原生多模态旗舰主打 agentic coding，FrontierCode 2.0 拿到 19.7%、Terminal-Bench 4.0 提升 13 点，且比 GLM-5.3 少用 47% token，"token 效率"正成为开源 coding 模型的新对比维度。基础设施侧，OpenAI 自研 Git 后端 Pando 承载全部 monorepo，push 中位延迟降近 5 倍、每天传近 1PB，印证"agent 规模化会先把版本控制打爆"。争议方面，一篇声称"LLM 能直接读写神经网络权重"的论文被逐条拆解，作者指出其修复 Qwen 数学能力实为 steering/abliteration 套路。市场端 AI 泡沫担忧持续，半导体 ETF 跌 3.79% 进入熊市，迈威尔科技因 1150 亿美元收购 Lumentum 单日重挫 12.72%。

  • Agent 规模化撞上基础设施墙：OpenAI 自建 Pando 应对 Codex 并发写代码、Databricks 训练任务量涨 8 倍、SGLang HiCache 把缓存命中率从 30% 拉到 95%，瓶颈正从模型转向版本控制与推理吞吐
  • 超长上下文效率竞赛：Latent Sparse Attention 在 10M token 下 prefill 提速 22.7 倍，Mistral Large 4 主打 token 效率，长上下文成本成为新的竞争焦点

⭐ 精选内容

Mistral Large 4（Le Chonk）开放权重：1T 原生多模态旗舰主打 agentic coding，FrontierCode 2.0 拿 19.7%、Terminal-Bench 4.0 提升 13 点 ｜ 欧洲主权 AI 的最强开源 coding 模型

三周前 preview 的 1T 参数旗舰正式开源权重，仅靠继续 scale RL 就在 FrontierCode 2.0 拿到 19.7%（领先 GLM-5.3、Kimi K3、DeepSeek V4.1 Flash），Terminal-Bench 4.0 从 28% 提到 41%，Artificial Analysis Coding Agent Index 上与 GLM-5.3 基本打平但少用 47% token。新增 Low/Medium/High 三档 reasoning 模式做成本-性能权衡，强调从零在欧洲基础设施训练、可自托管。值得记的是「token 效率」正成为开源 coding 模型的新对比维度，但全部数据为厂商自报口径，需等第三方复测。

来源：mistral.ai

OpenAI 自研 Git 后端 Pando 承载全部 monorepo：push 中位延迟降近 5 倍、每天传近 1PB，因果一致性同时满足写扩展与读带宽 ｜ agent 规模化先压垮版本控制

为应对 Codex 带来的并发写代码压力，OpenAI 自建 Git 服务 Pando 并已全量上线。文章从 Git object storage 基本模型讲起，对比三阶段提交与 WAL 两类分布式 Git 服务模式的取舍，最终选因果一致性（causal consistency）同时满足「写可水平扩展、读能跑满带宽」。完全兼容 Git 协议与客户端，工程师和 agent 无需改工作流，并回馈了 Git 上游。对做大规模 agent 并行写代码的团队，这是一条「agent 规模化会先把版本控制打爆」的完整架构决策链。

来源：openai.com

Realtime-Bench 揭示 agent 真实瓶颈在实时性而非推理：wall clock 下最强模型通过率仅 36%，暂停时钟后高推理模型能到 70-80% ｜ 判断 agent 会在哪类任务崩掉的高密度指标

Import AI 479 重点介绍 Realtime-Bench：50 个交互式游戏与网页任务，拆成 RT-Perceive（时序状态感知）、RT-Deliberate（按剩余时间调整思考长度）、RT-Act（择时行动）三维度，并设 wall clock / paused clock / token clock 三种时钟条件。结果很扎心——GPT-6 Astra 在 wall clock 下通过率仅 36%，暂停时钟后高推理模型能到 70-80%，说明当前 agent 的瓶颈不在推理能力而在实时响应。对做 Computer Use、实时交互 agent 的人，这是比静态 benchmark 更贴近真实失败模式的代理指标。另附 DIA 太空对抗报告与 Genie 4 短评。

来源：importai.substack.com

Legora CTO 复盘法律 Agent：客户 trace 一条都看不到，靠 3 工程师 + 3 律师自建模拟环境做 eval，一次发布把引用准确率从 70% 拉到 99% ｜ 不可见数据下的 agent eval 方法论

Latent Space 访谈 Legora CTO Jacob Lauritzen，18 个月做到 1 亿美元 ARR、1800+ 客户。核心矛盾是法律 Agent 的 trace 属于律所客户、团队一条都看不到，解法是用 3 名工程师 + 3 名律师搭建仿客户真实工作的模拟环境（如 1 万文件 data room 做尽调、要求 agent 报出正确 red flag），把 trace 改写成脱敏版本、把失败收敛到 10-20 类 failure mode，生产中用 feature flag 挂廉价 LLM check。另有 100 人 legal engineer 池（3-4 年大所经验 + CS 学位）、全栈锁 Azure、对法律检索等窄任务 post-train 开源权重、所有生成内容附 citation 并高亮源 PDF bounding box。两篇访谈内容重叠，合并阅读。

来源：latent.space（eval 篇） ｜ latent.space（产品篇）

AWS 官方拆解 agent 成本结构：一次任务不是一次调用而是 search→read→refine→verify→decide 循环，用 SeqKD 蒸馏小模型降本 ｜ agent 从 demo 到生产的降本配方

以「购物助手 agent」为例讲清 agentic 应用的成本结构：每步单独计费，规模化后单任务成本会吃掉 ROI。解法是 sequence-level knowledge distillation（SeqKD）：用前沿 teacher 生成多步 trajectory，靠程序化 grader 只保留真正解出任务的轨迹，编码成 SFT 数据训练小模型，无需 teacher logits 或 RL 基础设施，闭源 API teacher 也能用。文中点出 agent 场景的特殊价值——被复制的序列就是行为本身，因此蒸馏能同时传递推理与多步动作。适合被推理成本卡住、想把 agent 推到生产的团队，但绑定 SageMaker 单一厂商栈。

来源：aws.amazon.com

「LLM 能直接读写神经网络权重」被逐条拆解：识别小网络靠首层权重 L2 norm 热力图（三行 Python），修复 Qwen 数学能力实为 steering/abliteration 套路 ｜ 如何识别能力夸大的批判框架

针对一篇声称 GPT-6 Astra 能原生编辑 0.8B Qwen 权重提升数学能力的论文，作者逐条拆解其「超人类」结论：识别小网络玩什么游戏靠输入通道已标注 + 首层权重 L2 norm 热力图，三行 Python 可复现；修复 Qwen 数学能力实际是模型 32k token 后陷入循环，Astra 用的是「写循环/不循环文本对 → 测权重贡献 → 剪枝」的 steering/abliteration 套路，人类研究员同样会做。核心观点：直接改权重像直接改编译后二进制，可行但不是最优路径，LLM 帮 AI 研究的正确姿势是改进训练而非魔法调权重。读完能拿到一套判断「能力夸大」的可复用框架。

来源：seangoedecke.com

VLA 上真机的四类物理瓶颈：多相机数百 visual token 把控制环压到 5-10Hz、固定视角盲区、2D RGB 无度量深度、相机 ISP 自动曝光让像素剧变 ｜ 具身落地的失败模式清单 + 论文索引

文章指出 VLA 在 demo 里看似解决了机器人操作，上真机就暴露四类瓶颈：多相机高分辨率图像产生数百 visual token，transformer 前向 100-200ms 把控制环压到 5-10Hz，物体滑落来不及反应；固定第三人称相机与腕部相机各有遮挡/丢失目标的盲区，现有策略常死盯一路；2D RGB 无度量深度导致抓取对位偏移；商用相机 ISP 的自动曝光/增益/锐化在光照变化下让像素剧变，训练分布外的策略直接失效。随后逐篇介绍 FastVLA（语言-视觉注意力剪枝，FLOPs 降 35-59%、真机延迟降 20%）、FocusVLA（按阶段在静态相机与腕部相机间动态路由）等五项工作，均带 arXiv 编号与真机数字，可作为 VLA 工程落地的失败模式清单与论文索引。

来源：harpreetsahota.substack.com

自建 30 例带陷阱 benchmark 实测 agent skill：今天的 Claude 无 skill 也能躲开几乎所有陷阱，skill 只在模型知识最弱处生效 ｜ skill 到底还有没有用的实证

作者为「让 coding agent 做数据分析更靠谱」写了一个 agent skill（每条规则来自论文或官方文档），自建 30 个带陷阱的案例（小计行被加总、join 扇出重复订单、平均的平均、p99 被平均、辛普森悖论等），在 Haiku 5.5 / Sonnet 5.5 上做有/无 skill 对照，用 Sonnet 做 LLM judge 三票打分。结果：无 skill 时已达 58/61 与 60/61，skill 只补上零星漏判。三个可复用发现：skill 只在模型知识最弱处生效（训练截止后的 TypeScript 7 升级任务从 10/18 提到 17/18）；先怀疑自己的测试用例再相信 baseline 失败；skill 不激活等于不存在——把 description 从「列数据类型和陷阱名」改成「说明何时加载」，触发率从 7/20 提到 20/20。样本小（每臂一次运行），结论需自行验证。

来源：dev.to

Why Leibniz Couldn't Find the Mind Inside the Mill (Joscha Bach)

📍 来源：ML Street Talk | ⭐ 3/5 | 🏷️ Research, Agent, Interview | ⏱️ 01:37:07

Joscha Bach提出Machine Consciousness Hypothesis：意识是一种生物学习算法，自组织学习的机器可能以同样方式发现它。讨论为何不存在意识的图灵测试、棋类程序已是zombie、伪造心智有时比构建更难，并串联Leibniz's mill、Searle到Nagel的解释鸿沟、IIT及其被指伪科学的争议、Gödel形式系统极限、Mike Levin的形态发生与心智同构假说。对关注Agent本质与智能边界的从业者有概念启发，但偏哲学而非工程落地。

💡 推荐理由： 认知科学家Joscha Bach深度探讨意识与学习算法，哲学思辨强，但对LLM/Agent工程实践的直接指导有限
