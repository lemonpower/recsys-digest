⭐ 精选内容

OpenAI 首次公开内部 coding agent 加速研发的量化数据：2-4 小时研究任务成功率半年从 23% 升到 46%，但「锯齿前沿」明显 ｜ agent 真实能力边界的一手标尺

3-10 月间，agent 独立完成 2-4 小时任务成功率 23%→46%，4-8 小时任务 13%→35%；但任务类型差异极大——监控训练 run 达 79%，启动训练 run 仅 35%，写推理/服务栈代码仅 25%。成本侧中位数研究员日耗 API $2,400（+62%）、P90 达 $23,000（+105%）；调研显示研究员愿用 30% 团队算力或 40% headcount 换三个月 frontier coding agent 使用权。这是判断「agent 到底能替研究员干多少活」最直接的一组数字。

来源：openai.com

OpenAI 官方拆解 Codex sandbox：permission profiles 分层叠加文件系统与网络限制，macOS seatbelt / Linux landlock+seccomp / Windows 三平台各自实现，并演示给 MCP server 套沙箱 ｜ coding agent 权限模型的一手底稿

讲清了几个关键取舍：为什么默认让 Codex 在用户现有环境跑命令而非丢容器、harness 如何借沙箱执行、网络代理怎么实现。文末给出 `codex sandbox` 命令用法与「给 MCP server 套沙箱」的复用示例。与 Simon Willison 的 external sandbox（第三方视角）互补——这是官方一手实现细节，做 agent 权限边界的人可直接对照。

来源：openai.com

Meta 广告排序用 agent 做「技术扩散」：SMT 模板化 + Ranking Engineer Agent，两年交付 5,000+ technique-model 组合、单模型工程时间降 92%、预计年省 $45M+ 算力 ｜ 大规模模型 fleet 的扩散流水线

两篇工程博客讲同一件事的两面：Standard Model Templates 把模型设计收敛到可复用模板，让 technique 在 template 层验证一次即覆盖所有派生模型；剩下的判断类工作（选哪个 technique 给哪个模型、超参搜索开多宽、为什么没涨点）交给 agent，拆成 discovery / generalization / adoption 三段。自 2026 年 3 月起 agent 承担 60%+ 的 propagation 工作，工程效率 3x、部分组合训练算力中位数降 4x。核心洞察是「模型数量膨胀后，瓶颈从发明技术变成把技术铺到每个模型」——对维护多模型矩阵的团队是可迁移范式。

来源：engineering.fb.com（SMT 模板化） ｜ engineering.fb.com（REA agent 扩散）

Airbnb 用「cost per task」运营 coding agent：五周涌入 8 个新模型、三分之二请求转向新模型，官方 benchmark 已无法反映自家任务表现 ｜ agent 成本治理与模型路由的度量底稿

做法是上线前用 cost per task（完成一个任务所耗全部 token 的标价成本）+ 自建 eval 选型，上线后用 CloudWatch 的 Bedrock 运行时指标（InvocationLatency、TTFT、OTPS、InvocationThrottles、EstimatedTPMQuotaUsage、CacheRead/WriteInputTokenCount）观测，两者不一致时回溯原因，并据此设定每个模型的默认档位与 reasoning effort 上限。对做 agent 成本治理、模型路由、eval 闭环的团队，度量口径与监控清单可直接照搬。

来源：aws.amazon.com

SageMaker JumpStart 上线 Model Leaderboard：70+ 开源权重模型同一套评测口径横评，质量分拆 BBH/GPQA Diamond/MMLU-Pro 不混总分，性能与成本按标准化负载实测 ｜ 解决「各家 model card 口径不一」的选型工具

关键点是所有数字由 AWS 自测：质量分三个推理 benchmark 分开呈现，性能与成本打到每个部署配置上实测，再按 use case profile（默认 Max Context）与 optimization goal（Balanced / Cost optimized）切视图。能从 shortlist 直接走到部署。局限是只在 JumpStart 生态内、benchmark 仅三个且为厂商自测——但比拼接各家 model card 有实质增量。

来源：aws.amazon.com

微软 agent-framework PyPI 被投毒：1.26.1 / 1.26.2 相隔 33 分钟上传，靠 .pth 启动钩子在 Python 启动即执行，窃取 Azure managed identity 与 OIDC token ｜ agent 供应链安全的应急样本

恶意代码没利用任何云漏洞，只读取 agent 环境本来就持有的东西——环境变量 API key、dotfile token、宿主可即时签发的身份；1.26.2 还额外收集 GitHub Actions 凭证。关键细节是「仅 pin 回 1.26.0 不足以清除已落地的启动钩子」，需在不启动 Python/pip 的前提下检查暴露、隔离 CI runner、重建环境。核心论点是 agent 不应持有任何 secret，应走 secretless 路径。任何在 CI 里 pip install agent SDK 的团队都该照做一遍。

来源：akeyless.io ｜ blog.ogwilliam.com ｜ theregister.com

Amazon Science 用 proof assistant 给 agent 数学证明上「编译器级」保险：生成与检查交错进行，把幻觉挡在门外 ｜ agent 可靠性的形式化兜底范式

AutoCorrode 套件给出三个工具——I/Q（agent 接管活的 Isabelle 会话）、I/R（agent 与人类并行开发证明但不夺控制权）、Isabelle Assistant（开箱即用聊天窗口），并演示 Claude Opus 4.6 用 Isabelle 形式化 √2 无理数证明、自行纠正「N 个连续合数」错误证明。对关心 agent 可靠性、MCP 工具接入、形式化验证的人，是「用确定性检查器兜住生成模型」的可复用工程底稿。

来源：amazon.science

加州发布 AI 安全框架下一步：州级强制基线标准 + 全阶段独立安全测试 + 紧急关停权 + 对递归自我改进（RSI）设上限 ｜ 美国州级最激进的前沿模型监管文本

四项新内容：由州而非企业设定所有 AI 公司必须遵守的基线标准，训练/开发/部署全阶段接受独立安全测试；扩大安全事件报告范围并赋予州政府紧急关停模型的权力；对 RSI（模型可自行设计后继模型）设开发与使用上限。报告由 Jason Goldman、Gillian Hadfield、Alondra Nelson、Rob Reich 参与撰写，正与州议会推动立法落地。对在加州训练/部署模型的团队，直接关系未来合规成本与审计义务。
